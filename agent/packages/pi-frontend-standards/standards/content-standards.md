# Frontend Content Standards

## Headings

A heading should identify at least one of these:

- What the page or section is
- What the user can do
- What problem the feature solves
- What result the product produces

Prefer concrete headings:

```text
Give coding agents the decisions behind your repository
Review failed inspections by job
Connect QuickBooks to JobNimbus
```

Replace broad mood claims such as these:

```text
Your work should compound
Meet the future of operations
A better way forward
```

## Supporting copy

Use concrete nouns and active verbs. Name the capability, mechanism, result, and relevant scope.

Prefer:

```text
Lore indexes architecture decisions, meeting notes, and prior agent sessions so coding agents can retrieve cited project context.
```

Replace:

```text
Lore transforms how modern teams unlock the power of collective intelligence.
```

## Buttons and links

Use specific actions:

```text
Install CLI
Connect repository
Create dashboard
Invite teammate
View API docs
```

Use a broad label such as `Get started` only when the next step is genuinely general and no precise action exists. Labels such as `Explore`, `Discover`, `Learn more`, and `Try it` need a concrete object or a more exact verb.

## Feature descriptions

Structure feature copy as:

```text
Capability
Mechanism
Result
Constraint or scope
```

Example:

```text
Retrieve prior decisions

Lore indexes repository notes and agent sessions, then returns cited context to supported coding tools. Developers can inspect each source before accepting a recommendation.
```

## Claims

Use measurable or testable claims where possible. Qualify beta behavior, planned integrations, performance estimates, and unverified outcomes. Replace absolutes such as `Never lose context again`, `Works with every tool`, or `Eliminates hallucinations` with a bounded description of current behavior.

## Interface voice

Use sentence case. Product UI should orient, report status, and name actions. Marketing copy should still identify the user, task, mechanism, or result. Remove prompt language, design commentary, and claims that could fit an unrelated product.
